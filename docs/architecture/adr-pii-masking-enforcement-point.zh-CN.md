## 为什么

`SemanticFieldDescriptor.value_semantics.pii: bool` 在 v4.1 进入 schema
与指纹域，但本切片对掩码**没有运行时实现**。原因是结构性的：编译证据
只携带指纹——该层根本没有可掩码的字段值。真正的暴露面是**结果行**，
而结果行在证据链之外流转。本 spike 梳理结果行的序列化路径，并评估
三个候选执行点，使后续变更从一个已定的接缝开始，而不是重新争论。

## 当今结果行跨越的边界

1. **适配器执行**——每个适配器返回有界结果，其行是标量元组
   （`nl2data_core/adapters/models.py` 强制每个单元格为
   `str | int | float | bool | None`）。这是库内物理列值变成进程内
   数据的唯一位置。
2. **工作流 outcome**——runner 将适配器结果包装进执行 outcome；受保护
   结果同时生成 `result_fingerprint` 供 `ResultLineageEvidence` 使用
   （行本身从不进入证据）。
3. **Facade 边界**——`facade.aquery(...)` 把 outcome（含
   `result.rows` 与 `result.column_names`）交给宿主应用。
4. **Demo / 导出**——demo 入口直接打印 `outcome.result.rows`；任何
   宿主侧导出（CSV、notebook 渲染）都从同一个 facade 结果对象序列化。
   库侧没有导出 API，因此"导出"是由 facade 结果驱动的宿主行为。

## 候选执行点

### A. 结果级义务（类比 `mandatory_filter_fingerprints`）

在规划期声明按字段的掩码义务，并在 artifact-guard 边界校验，
与强制过滤义务类似。

- **优点**：复用现有义务/校验机制；义务以指纹形式可审计；执行前
  fail closed。
- **缺点**：义务校验的是*意图*而非输出。行仍以未掩码状态离开适配器；
  即便义务校验正确，也无法阻止从未掩码的列到达 facade。无论如何
  仍需要第二个输出侧机制。

### B. Facade 层导出过滤器

在 facade 把结果交给宿主之前掩码（或丢弃）`pii` 字段。

- **优点**：面向宿主负载的单一收口；贴近消费者；策略管道易接入
  （facade 已组合 policy scope）。
- **缺点**：太晚且易泄漏。结果对象已跨越内部边界；持久状态、评估
  证据以及任何内部消费者看到的都是未掩码行。非 facade 路径会被宿主
  侧导出绕过。在消费边缘掩码与库的 fail-closed 风格相悖：暴露应在
  数据流转*之前*阻止，而不是在*之后*删改。

### C. 适配器后处理契约（推荐）

适配器在构造结果前对行做后处理：任何绑定到 `pii=True` 语义字段的列，
都在适配器 execute 步骤内被掩码（或丢弃），由绑定加上经过校验的执行
上下文携带的掩码义务驱动。

- **优点**：掩码发生在**数据离开进程边界之前**、在**所有结果行都会
  跨越的单一收口**上；每个下游消费者（facade、demo、评估、持久状态、
  宿主导出）自动继承掩码数据，无需各自的消费侧逻辑；与适配器本就
  拥有行级整形规则（行界、标量约束）的现状一致。
- **缺点**：需要 `pii` 字段身份以仅指纹的方式到达执行上下文
  （经字段→列绑定派生，遵循物理边界规则）；适配器必须保持确定性，
  结果指纹才稳定；掩码会改变结果值，因此结果指纹必须在**掩码之后**
  计算（掩码输出即规范结果）。

## 决策

后续变更采用 **C（适配器后处理契约）** 作为执行点，并保留
**A（结果级义务）** 作为*声明与审计*机制：义务声明哪些字段必须掩码
并在执行前校验；适配器后处理器是满足这些义务的*执行*机制。
**B 被否决**：消费边缘的删改是便利功能，不是边界。

后续变更必须明确：

1. `pii` 字段身份如何以仅指纹方式从描述符传递到执行上下文
   （绑定派生，绝不携带原始描述符内容）。
2. 掩码算子（哈希、丢弃、删改）及其确定性保证，使
   `result_fingerprint` 与离线重放保持稳定。
3. 掩码先于指纹计算：`ResultLineageEvidence` 描述的是*掩码后*的结果。
4. Fail-closed 默认：无法解析的 `pii` 义务应使执行失败，而不是让
   未掩码的行通过。

在该变更落地之前，`pii` 保持 schema + 指纹属性，本文档即为延迟掩码
行为的记录 ADR（与把值语义纳入指纹域的 ADR-030 互为姊妹篇）。
