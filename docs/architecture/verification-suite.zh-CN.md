# 验证套件

> **本页为简体中文翻译**。规范语言为英文；如与
> [英文原文](verification-suite.md)冲突，以英文为准。

验证套件是已批准语义程序集与不可变已发布 Bundle 之间的发布门禁。冻结的
`VerificationPlan` 将已批准草稿修订绑定到有界冒烟用例和语义契约用例。
计划属于生命周期内容：修改计划会使批准失效，但计划不会进入 Bundle
规范载荷或语义指纹。

## 分层与策略

各层按固定顺序执行。Layer 1 由核心拥有，在任何外部工作之前验证草稿、评审、
计划绑定、Bundle 结构和身份、清单派生与等价性、作用域、兼容性及计算字段约束。
Layer 2 在受控夹具上执行受治理的规范 Semantic IR。Layer 3 在执行输入相同时
复用同一受保护观察值，但独立评估封闭的语义契约 DSL。

`compatibility-v1` 只要求 Layer 1，并明确将 Layer 2/3 标为非必需。
`production-v1` 要求三层全部执行，Layer 2 和 Layer 3 各至少有一个启用用例，
且每个必需用例都必须通过。缺少夹具、密钥解析器、能力或服务时不得降级策略。

## 执行信任边界

`VerificationExecutor` 可替换，并由能力指纹标识。SQLite 参考执行器组合现有的
IR 验证、编译、守卫、治理、授权、适配器执行、结果保护和夹具生命周期边界。
用例、层和套件均有有界截止时间；取消向下传播；始终尝试重置和释放资源。

执行器返回有界、瞬态的 `VerificationObservation`。其中可暂存评估断言所需的
受保护标量行，但随后立即归约并释放。观察值、查询、物理名称、部署引用、凭据
及后端异常不得进入持久化证据或 Admin DTO。

## 证据身份

用例、层和套件证据仅包含状态、计数、有界问题码、版本和指纹。套件证据绑定
计划、策略、草稿修订、Bundle、接受清单、租户/来源作用域、核心运行器以及外部
执行器。持续时间属于运维元数据，不参与证据指纹。单边、过期或漂移身份均失败关闭。

发布在一个原子操作中存储 Bundle、清单、证据、审计、版本和取代元数据。没有
证据的旧发布归类为 `legacy_unverified`；它们仍可读取，但不能满足
`production-v1`。
