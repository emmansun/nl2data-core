# ADR-045：计算字段操作符白名单及其记录在案的拒绝项

## 为什么

计算字段（`SemanticEntityDescriptor` 上的 `CalculatedField`，v4.2）
在编译期把声明的表达式树展开为适配器原生输出。表达式语言是一个
**封闭白名单**，仅含六个操作符：`field`、`const`、`add`、`sub`、
`mul`、`div`。白名单之外的任何内容都会在定义期以 `CF_001` 拒绝 ——
表达式永远不会进入 IR（IR 只携带引用，不变量 N4），也永远不会在
查询期执行。

本 ADR 记录每一项拒绝**及其替代路径**，使未来的切片通过决策扩展
语言，而不是靠 pull request 的偶然。以下每项拒绝都对照三个不变量
评估：指纹确定性（展开输出必须跨函数库版本与适配器方言字节稳定）、
规划器只引用（模型引用受治理的名称，从不组合表达式）、以及
fail-closed 治理（每个构造在执行前都必须可授权、可审计）。

## 记录在案的拒绝项

### 任意函数调用 — 拒绝

函数库跨数据库引擎与版本存在差异；一个声明在 SQLite 和 PostgreSQL
上语义不同会破坏双适配器等价性保证（设计 D7）和展开身份的指纹
确定性（设计 D12）。

**替代路径**：版本化扩展包 —— 未来的切片可以按能力声明一个有界、
已指纹化的函数集合，使声明的集合随 Bundle 一起传播，适配器可以
拒绝其无法确定性展开的内容。

### 子查询 — 拒绝

子查询与规划器只引用（N4）冲突：模型将组合查询结构，而不是引用
受治理的名称。它还会把嵌套授权复杂性拖进编译器（子查询内部适用
哪些 scope？），而对 v4.2 没有任何价值。

**替代路径**：多实体规划（已治理的连接词汇表，查询期编译）处理
跨实体问题；NamedQuery（v4.4）处理参数化命名查询。

### 字符串拼接与正则表达式 — 拒绝

字符串组合是 LLM 规划器滥用面最大的构造（格式化字符串注入到输出、
正则复杂度炸弹），也是方言分歧风险最高的构造（拼接操作符、正则
方言、排序规则处处不同）。

**替代路径**：留待 v2 决策；或在扩展包机制落地并具备按适配器
一致性验证之后再引入受控 UDF。

### `CASE WHEN` 组合 — 拒绝

条件逻辑属于 Metric 过滤子句（v4.3）：Metric 可以声明受守卫的
聚合，作为命名语义被评审、指纹化和授权。把分支逻辑嵌入计算字段
会绕过这一评审面。

**替代路径**：Metric/TimeSemantics（v4.3）过滤子句。

### 聚合组合（`SUM(a) / COUNT(DISTINCT b)`）— 拒绝

按操作数聚合（每个操作数不同的聚合）属于 **Metric 领域**（v4.3），
不是计算字段的扩展。计算字段把一个表达式展开在行值之上 —— 可能由
选择的聚合种类统一聚合 —— 而聚合组合需要另一种规划模型（按操作数
的聚合绑定、`DISTINCT` 处理、空集语义）。在这里开放它会以更弱的
授权面复制 Metric 的规划职责。这是一条记录在案的**非目标**，
不是推迟到 v4.3 的功能请求。

**替代路径**：Metric（v4.3）派生指标。

## 白名单包含什么

`field`（数值叶子，经物理绑定解析）、`const`（仅 int —— 拒绝
float 和 bool 以保持表达式指纹域稳定；负 int 有效），以及算术
操作符 `add`、`sub`、`mul`、`div`（真除法；SQL 方言以 CAST 强制
声明的输出类型，SQLite 整数除法截断由一致性夹具 `7 / 2 → 3.5`
捕获）。`zero_division_policy`（`null` | `error`）按字段声明，
由守卫展开强制（`error` 策略下为 `CF_005`）。

## 相关的强制不变量

- **CF_004（双向 pii 隔离）**：表达式绝不引用 `pii: true` 字段，
  Bundle 也不能对已被已声明计算字段引用的字段应用 `pii`。未来
  字段掩码策略目标必须接入同一检查。掩码由适配器对输出列的后处理强制（见
  [pii 掩码 ADR](adr-pii-masking-enforcement-point.zh-CN.md)）；
  派生输出列会把未掩码衍生的值带过该执行点 —— 这是结构性绕过。
  fail-closed；"先掩码再计算"推迟到未来专门的 ADR。
- **不可组合**：计算字段不能引用另一个计算字段（`CF_002`）——
  每个输出一个受治理定义，没有传递性指纹或掩码链。
- **占位符不可表达**：保留的 NamedQuery 占位符 schema（v4.4）在
  表达式树内结构上不可达；v4.4 扩展白名单时不得开放这条路径。

## 后果

- 扩展白名单需要新的 ADR（或对本 ADR 的修订）加上双适配器
  一致性覆盖，任何操作符才会被接受。
- [ADR 注册表](adr-registry.md) 是唯一的编号权威；新 ADR 从统一
  列表中取下一个空闲编号。
